# 制药行业 HCP Personalized Engagement Assistant

- 为药企量身定做的，为 HCP (Health Care Professional) 建立数字分身，提供个性化 Engagement 的建议
- 内建 hcp-twin-mcp MCP，全网检索 HCP 的信息（个人信息、职业轨迹、科研动向、活动热力、级别标签等），生成数字分身与 HCP 洞察
- 搭建 medical-knowledge-base RAG：**按专科按需**灌注前沿学术资料 + HCP Engagement 合规文件（不做全科预灌）
- 内建 hcp-engagement-agent 智能体，根据数字分身与洞察推荐个性化 engagement 建议

# 产品包含：

## Web App「HCP Personalized Engagement Assistant」交互入口

四个 Tab：

| Tab | 职责 |
|-----|------|
| **数字分身** | 入口为**已建分身列表**；新增/修改进入编辑；详情含一句话洞察、级别标签、职业轨迹；可删除 |
| **HCP洞察** | 一句话洞察、科研方向（含主要成果）、活动热力四列表、已知近期学术活动、兴趣与证据（可链） |
| **一人一策** | 方案以**选项卡**展示；页底嵌入与 Agent 的短对话 |
| **HCP Engagement Agent** | 标准对话智能体：历史上栏（cookie）、附件上传、面板可 resize |

## hcp-twin-mcp MCP

- 全网采集公开信息：职业轨迹、文献、科研动态、活动热力等
- 写入香港 Postgres 数字分身；绑定文献检索号（AuthorIds）
- **级别打标**（`hcp_tier` + `role_tags`）：按公开影响力分层，禁止处方潜力打标
- 形成洞察：在做什么、对什么感兴趣、可能想要什么

### HCP 文献查询站点（按优先级）

**准入**：公开 API · 国内可访问 · 免登录（不做爬虫）。

| 优先级 | 站点 | 网址 | 用途 |
|--------|------|------|------|
| P0 | PubMed | https://pubmed.ncbi.nlm.nih.gov/ | 生物医学主库；PMID / 作者簇 |
| P0 | ORCID | https://orcid.org/ | 作者唯一号；拉作品 |
| P0 | OpenAlex | https://openalex.org/ | 作者 / 作品图谱 API |
| P1 | Europe PMC | https://europepmc.org/ | PubMed 互补 |
| P1 | Crossref | https://www.crossref.org/ | DOI 元数据归并 |
| P2 | ClinicalTrials.gov | https://clinicaltrials.gov/ | 试验旁证 |

消歧顺序：`orcid` → PubMed 作者簇 → `openalex` → Europe PMC / Crossref。详见 [`literature-sources.md`](../knowledge/mcp-hcp-virtual-twin/literature-sources.md)；设计 [`mcp/mcp-design.md`](./mcp/mcp-design.md)。

## medical-knowledge-base RAG

- **按专科按需**学术索引（Twin specialty/themes 触发）；同专科缓存复用
- HCP Engagement 合规文件（手灌种子 + 租户 SOP）

## hcp-engagement-agent 智能体

- 根据数字分身洞察 + 学术 RAG + 合规 RAG
- 推荐个性化一人一策；支持对话迭代与附件上下文

## 典型用例

复旦大学附属中山医院 朱同玉教授

## MVP 划分（7 个可独立闭环）

原则：每个 MVP 交付后可**单独演示一条完整用户/运维闭环**；上游未就绪时用 fixture / mock 代替，不阻塞本环验收。建议实现顺序 MVP-1 → 7；**MVP-4 可与 MVP-2/3 并行**。

| MVP | 名称 | 独立闭环（验收一句话） | 主覆盖功能 | 依赖 |
|-----|------|------------------------|------------|------|
| **MVP-1** | 数字分身工作台 | 查询→消歧→确认保存→列表/详情/改/删；数据进香港 Postgres；浏览器只调 BFF | F-WEB-001–016、035–036、040；F-MCP-001–017、025、030–032、035 | `domain` + `db` + 壳 |
| **MVP-2** | Twin 情报构建 | 确认后异步 Stage A–E，进度可查；职业/科研/热力/标签/Insights 落库可读 | F-MCP-018–024、026–029、033–034；F-WEB-014（强化） | MVP-1 |
| **MVP-3** | HCP 洞察报表 | 洞察 Tab 八块可读可链；一句话洞察与分身同源（Agent 合成） | F-WEB-017–025、037、041；F-AGT-001、001a–d、005、008–010、028 | MVP-1；洞察内容可 fixture，live 靠 MVP-2 |
| **MVP-4** | 合规 RAG 底座 | 手灌合规种子 → `retrieve_compliance` 抽检命中含 `clause_id` | F-RAG-001–007、002a–d、009–011、013、018、023–024、026 | Qdrant + corpus；可与 2/3 并行 |
| **MVP-5** | 专科学术按需库 | Twin 确认后 on-demand ingest → `retrieve_academic` 可按 specialty 命中 | F-RAG-008、012、014–017、019–020、027；F-WEB-039 | MVP-1；Hybrid 底座可复用 MVP-4 |
| **MVP-6** | 一人一策 | 生成 3–5 方案（双引用）→ 合规闸门结构化结果 → 页底 `revise_options` | F-WEB-026–029、038；F-AGT-002–007、011–018、020–021、024–027、029–030 | MVP-3 + MVP-4（学术可 sparse） |
| **MVP-7** | Engagement Agent | `open_chat` 多轮对话 + 历史/附件/resize + 可选流式；横切 a11y/租户加固 | F-WEB-030–034、042–043；F-AGT-019、022–023；F-RAG-021–022、025 | MVP-1；对话可仅 Insights，完整引用靠 4/5/6 |

### 刻意不进前 7 个 MVP 闭环的能力

- 正式 MLR 电子签、CRM 回写、自动办会  
- 全科 / 全 PubMed 预灌、知网无授权爬取  
- Parent-Document（F-RAG-022）可作为 MVP-5 之后增强
