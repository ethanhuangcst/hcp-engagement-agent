# 测试策略与 Definition of Done

> as_of：2026-07-17  
> 依据：[`1.product-definition.md`](./1.product-definition.md)（MVP-1…4）、[`app/app-stories.md`](./app/app-stories.md)、四份 `*-function-spec.md`、[`4.install-dependencies.md`](./4.install-dependencies.md) §11  
> 原则：测试跟 **可独立闭环的 MVP** 走；CI 默认 **mock / fixture**；live 外网与真实 LLM 为可选门禁，不阻塞合并。

---

## 1. 目标与范围

| 目标 | 说明 |
|------|------|
| 证明闭环 | 每个 MVP 的「验收一句话」可自动化或可复现手工脚本验证 |
| 防回归 | Schema、MCP Tool、RAG 过滤、Agent 引用/合规、BFF 边界有契约测试 |
| 可控成本 | CI 零外网（`TWIN_MODE=mock`、mock `LlmClient`、本地 Qdrant 或内存替身） |
| 可观测 | `/api/health` + 结构化错误码进入断言与日志抽检 |

**范围**：`apps/web`、BFF、`hcp-twin-mcp`、`medical-kb`、`hcp-engagement-agent`、`domain`/`db`。  
**非范围**：正式 MLR 签批系统、CRM 回写、知网爬取、全 PubMed 预灌。

**样例 HCP**：复旦大学附属中山医院朱同玉（fixture + 可选 live）。

## 2. 测试金字塔

```text
        ┌─────────────┐
        │  E2E / ATDD  │  Playwright（浏览器 → BFF only）
        │  少量关键路径 │
        ├─────────────┤
        │  集成 / 契约 │  MCP Tools · RAG retrieve · Agent API · BFF
        ├─────────────┤
        │  单元        │  Zod · 纯函数 collectors · gates · normalize
        └─────────────┘
```

| 层 | 工具 | 谁写 | 何时跑 |
|----|------|------|--------|
| 单元 | Vitest | 各 package | 每次 PR / 本地 pre-push 可选 |
| 组件 | Vitest + RTL | `apps/web` | 每次 PR |
| 集成 / 契约 | Vitest | mcp / medical-kb / agent / db | 每次 PR（mock） |
| E2E | Playwright（Chromium headless） | `apps/web` 或 `e2e/` | 每次 PR：smoke；合并 main / 夜间：MVP 全路径 |
| RAG eval | `data/rag/eval-set.json` + 脚本 | medical-kb | MVP-3 门禁；周回归 |
| Live 抽检 | 手工或带 Key 的 job | 可选 | 发版前 / 周一次（不挡 PR） |

**隔离规则**

- 浏览器 E2E **禁止**直连 MCP `:3200`、Qdrant、LLM Key（断言网络目标 ⊆ 应用 origin）。
- Twin 采集用的 Playwright **仅**在 `hcp-twin-mcp` 进程；与 E2E Playwright **分目录、分依赖**，避免混用。
- Agent 单测 **mock `LlmClient`**；不在 CI 调 DashScope。

## 3. 按 MVP 的测试矩阵

| MVP | 必测闭环 | 单元 / 契约 | E2E / ATDD（对应 US） | 环境 |
|-----|----------|-------------|----------------------|------|
| **1** Twin 工作台 | 多开姓名标签；工作台子 Tab；列表仅打开；改/删在工作台；`build_twin` 进度→enrichment；职业轨迹 locale | MCP resolve/tag/build；Twin Zod；BFF；壳导航；`localizeCareer*` | US-WEB-001–004（045–046） | Postgres；产品 `TWIN_MODE=live` |
| **2** 洞察工作台 | 八块可读；`doing_now` 同源；嵌于工作台 | `synthesizeDoingNow` mock LLM；Insights GET | US-WEB-005 | fixture Insights |
| **3** 知识库 | 合规 retrieve 含 `clause_id`；学术 `ingest_on_demand`→`retrieve_academic`；F-WEB-039 | 双库不串；bind_safe；coverage；specialty 归一化 | medical-kb + BFF `/api/rag/ingest` | 本地 Qdrant + corpus |
| **4** Engagement | Options + 闸门 + `revise_options` + `open_chat` | 5 tools；gate；mode 隔离 | US-WEB-006–008 | mock LLM + MVP-3 chunks |

每个 MVP 至少：**1 条 happy-path 自动化** + **1 条失败/边界**（如未消歧、空合规、未选定 HCP 拒生成）。

## 4. 分层细则

### 4.1 单元（Vitest）

| 包 | 必覆盖 |
|----|--------|
| `@hca/domain` | Twin / Insights / Options / AuthorIds Zod 往返；禁止字段拒绝 |
| `@hca/db` | upsert 事务；同 `hcpId` 互斥（可测锁或失败码） |
| collectors | HTML/JSON fixture → 结构化字段；空窗 `no_public_evidence` |
| medical-kb | RRF 权重边界；filter；chunk citation 形状 |
| agent | Permissions；gate 降级；`open_chat`（无 hcpId）vs `revise_options` 入参；mode 隔离 |

**覆盖率门槛（SMART，见 §6）**：变更包语句/分支 ≥ 80%；关键路径（消歧门禁、合规强制检索、BFF 鉴权边界）行覆盖 **100%**。

### 4.2 集成 / 契约

| 对象 | 断言要点 |
|------|----------|
| MCP Tools | `TWIN_MODE=mock`：I-MCP-* 入参 Zod 失败 → 结构化 `MCP_ERROR`；resolve 未确认不写完整 Twin |
| medical-kb | `retrieve_compliance` 空结果可返回；学术/合规 **不串 collection** |
| Agent API | mock LLM：Options 含 `academic_refs`/`compliance_refs`；跳过 compliance tool → 失败或拒敏 |
| BFF | 非法 body → 4xx；成功写 Postgres；响应无堆栈 |

### 4.3 E2E（Playwright · Web_Testing）

- 入口：应用 URL（如 `http://localhost:3000`）；`networkidle` 后再取选择器。
- 脚本风格：同步 Playwright + headless Chromium；服务器用进程管理（或 monorepo `with_server` 类 helper）。
- **Smoke（PR）**：登录或匿名壳 → 数字分身列表可见 → Tab 门禁（未选定无洞察）。
- **MVP 路径（合并/夜间）**：按 §3 矩阵；朱同玉 fixture 预置或 mock MCP。
- 截图：失败时 `full_page` 附件进 CI artifact。
- **不**在 E2E 里启动 Twin 采集 Playwright 爬医院站。

### 4.4 RAG eval

- 用例：`data/rag/eval-set.json`（无客户 SOP 明文）。
- MVP-3：≥3 条合规问法，期望命中含 `clause_id` + `version`/`as_of`；专科 academic ≥1 条可命中（fixture 灌库后）。
- 指标：命中率、空结果率；周看趋势（架构可观测性）。

### 4.5 Live / 手工门禁（非 CI 阻断）

| 项 | 频率 | 通过标准 |
|----|------|----------|
| 朱同玉 `TWIN_MODE=live` resolve + AuthorIds | 发版前 | 满足字典 A9 / 活跃 P0 ≥1 |
| DashScope/Qwen Options 生成 | 发版前 | 3–5 条 + 引用字段非空（有库时） |
| Qdrant `bind_safe` | 部署检查 | health 报安全绑定 |

## 5. CI / 本地命令约定

| 命令（意向） | 作用 |
|--------------|------|
| `npm run lint` / `npm run typecheck` | ESLint + `tsc --noEmit`（workspaces） |
| `npm test` | 全仓 Vitest（mock） |
| `npm run test:coverage` | 覆盖率报告；不达标 fail |
| `npm run test:e2e` | Playwright smoke |
| `npm run test:e2e:mvp` | 按 `MVP=n` 跑对应规格路径 |
| `npm run test:rag-eval` | eval-set（需本地 Qdrant） |

PR 必绿：`lint` + `typecheck` + `test` + `test:e2e`（smoke）。  
`test:e2e:mvp` / live / rag-eval：标签触发或夜间。

## 6. SMART Definition of Done（DoD）

任一 **用户故事** 或 **MVP** 标记「完成」前，须同时满足下列条款。每条按 SMART 可判定。

### 6.1 故事级 DoD（默认）

| # | 准则 | S | M | A | R | T |
|---|------|---|---|---|---|---|
| D1 | AC 全过 | 对应该 US 的 Gherkin / 规则清单 | 场景 100% 有自动化或签字的手工记录（路径+日期+执行人） | 有 fixture/mock 即可跑 | 对应该 MVP 闭环 | 合入前完成 |
| D2 | 自动化绿 | 本故事触及的 Vitest + 相关 E2E | CI job 全绿；无 skip 关键 AC | 不依赖外网 Key | 回归防破坏 | PR 合并前 |
| D3 | 覆盖率 | 变更包 | 语句/分支 ≥ **80%**；消歧/合规强制/BFF 边界相关文件行覆盖 **100%** | Vitest coverage | 质量底线 | 同 PR |
| D4 | 类型与风格 | 变更 TS/TSX | `tsc` 与 lint **0 error** | 仓库脚本 | 可维护 | 同 PR |
| D5 | 契约 | 新增/改 F-* / I-* | 对应契约测试断言入参/错误码/出参关键字段 | mock 可测 | 与 function-spec 一致 | 同 PR |
| D6 | 安全边界 | 浏览器路径 | E2E 或集成断言：无 MCP/Qdrant/LLM Key 泄露到浏览器 | 网络/响应检查 | F-WEB-035 | 涉及 Web 的故事 |
| D7 | 文档 | 规格/故事/README | 行为变更则同步 function-spec 或 stories；无过期 TBD 批次（用 MVP-n） | diff 可审 | 可追溯 | 同 PR |
| D8 | 版本控制 | Git | 变更已 commit；无密钥进库；远程分支已推送（若团队要求） | `git status` / 钩子 | 可发布 | 标记完成前 |
| D9 | 验收签字 | 样例 HCP 或运维闭环 | 产品/开发一方在故事或 MVP 清单勾选「验收通过」并注明日期 | 演示 ≤ 15 min | 业务可见 | **T**：故事开发结束后 **2 个工作日内** |

### 6.2 MVP 级 DoD（在故事 DoD 之上）

| # | 准则 | SMART |
|---|------|-------|
| M1 | **独立闭环演示** | Specific：产品定义该 MVP「验收一句话」。Measurable：脚本或清单逐步可勾。Achievable：允许上游 fixture。Relevant：不依赖未宣布的下一 MVP。Time：MVP 排期结束日当天可演示。 |
| M2 | **健康检查** | `GET /api/health`（及 MCP/`medical-kb` health）对应该 MVP 依赖组件为 ok 或显式 degraded。 |
| M3 | **错误可修复** | 至少 1 条失败路径有用户可读文案（无 emoji 堆砌），与 F-WEB-040 / MCP 错误码一致。 |
| M4 | **数据驻留** | Twin/Options/session/manifest 在 Postgres；向量仅 Qdrant；无语料进 Git。抽检 `.gitignore` + 一次写入路径。 |
| M5 | **朱同玉锚点** | MVP-1+：CI mock 可用朱同玉 fixture；宣布 live 的发版（尤其 MVP-1 / MVP-4）前完成 §4.5 对应项。 |

### 6.3 明确「未完成」条件（一票否决）

- CI 红或覆盖率门槛未达标  
- 浏览器持有 LLM Key / 直连 Qdrant 或 MCP  
- Options 提案路径可跳过 `retrieve_compliance` 且无失败  
- `disambiguation_status=resolved` 却无活跃 AuthorIds（A9）仍当成功  
- 文档与行为明显冲突且未开 follow-up 故事

## 7. 缺陷分级与退出标准

| 级别 | 定义 | MVP 退出 |
|------|------|----------|
| P0 | 闭环不可用、数据损坏、密钥泄露 | **不可**宣布 MVP Done |
| P1 | 主路径错误但有临时手段 | 须有修复计划 ≤ **5 个工作日** 方可带病退出 |
| P2 | UI/文案/非关键路径 | 可进 backlog，不挡 Done |
| P3 | 增强/抛光 | 不挡 |

## 8. 角色与节奏

| 角色 | 职责 |
|------|------|
| 开发 | 单测/契约与实现同 PR；维护 fixture |
| 评审 | 查 DoD 勾选与覆盖率报告 |
| 产品 / 业务 | D9 验收签字；朱同玉场景走查 |
| CI | 强制 §5 PR 门禁 |

节奏：每个 MVP 结束做一次 **DoD 走查**（对照 §6.2）；每周看 RAG eval 与 live 抽检纪要。
