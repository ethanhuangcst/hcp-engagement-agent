# ADR-011: query_hcp 医院与科室过滤支持包含匹配

## 状态
已采纳

## 背景
`query_hcp` 可选过滤对 `hospital` / `department` / `city` 做归一相等（去空格、忽略大小写），不做模糊（mcp2-design §6）。调用方常用简称或短式：「协和医院」对「北京协和医院」，「中山医院」对「复旦大学附属中山医院」，「外科」对「肝胆外科」。归一相等在这些场景漏检，查询返回 0，调用方可能误判「库中无此人」，随后走不必要的库外检索或触发新增流程。姓名字段已有多档匹配，机构字段零容错成为唯一的漏检口。

## 决策
1. `hospital` 与 `department` 的过滤比对扩展为两档：
   - 档 0：归一相等（去首尾空格、转小写、连续空白合一），现状不变。
   - 档 1：包含匹配，归一后一方为另一方的子串。
2. 最小长度护栏：医院子串短边不少于 3 个字符；科室短边不少于 2 个字符（按归一后字符数计）。「医院」「协和」（各 2 字符）不触发档 1。
3. `city` 不变，仍归一相等；不引入城市模糊。
4. 作用范围：`query_hcp` 可选过滤，含 `hcp_id` 精确查询时的叠加过滤比对。不改变 ADR-009：写前查重门仍只按姓名规则与 `hcp_id`；疑似列表排序信号仍为归一相等优先。
5. 实现落点：`@hca/db` `filtersMatch`（twins.ts），MCP handler 不复制规则。

## 原因
- 过滤是供人判断的缩窄信号：过检（多返回几条）由人消歧，代价低；漏检（返回 0）引导调用方走错后续路径，代价高。
- 子串包含是确定性规则：无词典、无常量表、可单测，与 `nameMatchTier` 的固定字符串比较风格一致。
- 真实短式与全称绝大多数是子串关系；长度护栏挡住「医院」「科」这类泛词的高频误命中。
- 不选编辑距离：中文机构名差一个字常是两家不同医院，风险与收益不成比例。

## 后果
- 「内科」这类 2 字科室短词会命中「心内科」「消化内科」等同院多科室；查询场景可接受，写入门不受影响。
- 「中山医院」会同时命中广州、上海两家中山系医院：多条全量返回供人选择，本就符合多命中语义。
- 医院与科室各自只用「双向子串」一档，不做拼音、别名词典、编辑距离；将来引入标准机构名录时另立决策替换档 1。
- `filtersMatch` 的既有入参形状不变，返回从布尔改为命中与否语义不变（调用方拿到同一语义）；行为变化只出现在短边达标的子串场景，旧精确场景完全兼容。
