## 1. 范围与原则

### 1.1 Twin 是什么

HCP Virtual Twin（医疗专业人士数字分身）是**可审计的公开信息结构化画像**，用于：

- 展示 HCP Insights（UI）
- 驱动 `get_twin_insights` → Engagement Options（Agent + cn-hcp-pro）
- 触发 medical-kb 专科按需 ingest（`specialties` / `themes`）

**不是**：CRM 客户卡、处方分层库、非公开拜访记录库。

### 1.2 落盘文件

```text
data/twins/{hcpId}/
  identity.json          # 用户录入 + 身份锚点（Profile 子集）
  twin.json              # profile + career + research + activity + network + content + hco + flags
  insights.json          # 衍生洞察（独立版本号）
  career-timeline.json   # 可选拆分
  research.json          # 可选拆分
  heatmap/snapshots.json # 可选拆分（activity）
```

逻辑合并视图见 fixture；实现时按上表拆分或合并，**字段名保持一致**。

### 1.3 通用字段约定

凡**事实性**记录（非纯推断）应尽可能包含：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `source_url` | string | 事实记录建议有 | 溯源 URL |
| `source_type` | enum | 否 | 见 §12.1 |
| `as_of` | date (ISO) | 是 | 采集或确认日 |
| `confidence` | enum | 是 | `high` \| `medium` \| `low` |
| `evidence_snippet` | string | 否 | 短摘录 |
| `conflict_note` | string | 否 | 多源冲突说明 |

**推断性**字段（Insights、`may_want`、`*_hypothesis`）须可追溯到 `evidence_refs[]`，不得伪装成事实。

### 1.4 合规红线（cn-hcp-compliance）

| 禁止写入 Twin | 依据 |
|---------------|------|
| 处方量、份额、统方、销量潜力评分 | 《医药代表管理办法》负面清单 |
| 非公开 CRM 拜访记录 | 不得冒充公开活动热力 |
| 患者病历、可识别患者信息 | PIPL |
| 未授权私域联系方式（手机/微信）用于营销画像 | PIPL |
| 产品适应症、促销话术、MLR 状态 | 属租户 `data/tenants/`，非 Twin |

## 13. 字段 → Engagement Options 映射

| Twin / Insights 字段 | cn-hcp-pro 用法 | cn-hcp-compliance 旁注 |
|----------------------|-----------------|------------------------|
| `role_labels` | 负责人：MSL vs 代表 vs 市场 | 商业/医学分工 |
| `themes` / `trend_shift` | 内容主题 | 仅限租户提供的说明书范围 |
| `activity.events[].topic` | 会后跟进钩子 | 真实活动；机构同意 |
| `bucket=policy_media` | 不用代表促销路径 | 受众隔离 |
| `admin_roles` / `public_gatekeeper_roles` | stakeholder_notes | 须医疗卫生机构同意 |
| `msl_priority_topics` | Option 负责人=MSL | 非促销科学交流 |
| `compliance_cautions` | 每条 Option 合规旁注 | Fail-fast 输入 |
| `may_want.do_not_assume` | 禁止写进 Option 的假设 | 防统方/进院交换 |
