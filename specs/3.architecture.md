## 2. 系统目标与非目标

### 2.1 目标

在中国医药合规边界内，为指定 HCP 提供：

1. **Virtual Twin**：基于公开信息的数字分身（职业、科研、活动热力）
2. **Insights**：可解释的兴趣点与 unmet need 摘要
3. **Engagement Options**：3–5 条可执行、带学术与合规引用的互动建议
4. **Assistant**：在同一上下文上对话修订 Options

**P0 验收用例**：复旦大学附属中山医院朱同玉教授。

### 2.2 非目标（P0 不做）

| 非目标 | 原因 |
|--------|------|
| 替代正式 MLR | 输出为辅助建议，须人工审核 |
| 全渠道 CRM / 中台 | 行业缺口在「聊什么」，不在「有没有系统」 |
| 全科医学向量库预灌 | 按 Twin 专科 **按需 ingest** |
| Postgres 主库 | 规格选定 **本地 JSON** + Qdrant |
| 统方 / 处方 / 非公开 CRM 数据 | 合规与权限边界 |

## 3. 逻辑架构（五层）

```text
┌─────────────────────────────────────────────────────────────┐
│  表达层   apps/web — Twin / Insights / Options / Assistant   │
├─────────────────────────────────────────────────────────────┤
│  决策层   hcp-engagement-agent — 5 tools + 薄 LangGraph      │
├─────────────────────────────────────────────────────────────┤
│  知识层   medical-kb — academic_index ‖ compliance_index     │
├─────────────────────────────────────────────────────────────┤
│  感知层   hcp-twin-mcp — collectors → Twin / Insights JSON  │
├─────────────────────────────────────────────────────────────┤
│  约束层   cn-hcp-compliance + cn-hcp-pro + 人审 MLR          │
└─────────────────────────────────────────────────────────────┘
```

| 层 | 职责 | 不负责 |
|----|------|--------|
| 表达层 | BFF、页面、会话 UX、导出 | 爬虫、向量检索实现 |
| 决策层 | 编排检索、生成 Options、多轮修订 | 存储全量指南、抓取网页 |
| 知识层 | Ingest、Hybrid 检索、引用块 | HCP 画像构建 |
| 感知层 | 公开信息采集、消歧、Insights 衍生 | Engagement 文案生成 |
| 约束层 | Fail-fast、行业准则、说明书边界 | 业务数据采集 |

### 4.1 进程边界（硬规则）

| 规则 | 说明 |
|------|------|
| 浏览器只调 BFF | 禁止直连 MCP、Qdrant、LLM API Key |
| Playwright 仅在 twin 进程 | `apps/web` 不得依赖 `playwright` |
| 共享数据目录 | `HCA_DATA_DIR` 卷挂载到 web、twin-mcp；Agent 经库读写 JSON |
| 向量与结构化分离 | Twin/Options 用 JSON；知识块用 Qdrant payload + manifest |

### 4.2 部署单元（Docker Compose）

| 服务 | 副本 | 说明 |
|------|------|------|
| `web` | 1+ | Next standalone；无浏览器引擎 |
| `hcp-twin-mcp` | 1 | 含 Chromium；CPU/内存高于 web |
| `qdrant` | 1 | 自托管；`data/qdrant` 卷 |
| `redis` | 0–1 | P1 异步 Twin 构建 / 热力 cron |
| `nginx` | 1 | TLS 终止 |

**无 Postgres。**

## 5. 模块设计

### 5.1 表达层 — `apps/web` + BFF

**职责**：四页用户旅程 + API 网关。

| 页面 | 用户动作 | BFF 行为 |
|------|----------|----------|
| HCP Virtual Twin | 录入姓名/医院/科室 | `POST /api/twin/build` → MCP `build_twin` |
| HCP Insights | 查看画像 | `GET /api/insights/[hcpId]` → 读 JSON |
| Engagement Options | 生成方案 | `POST /api/engagement/options` → Agent |
| Engagement Assistant | 对话修订 | `POST /api/engagement/chat` → Agent + session JSON |

**BFF 模式**

- 短请求：同步返回 JSON
- 长任务（Twin 构建、on-demand ingest）：返回 `runId`，React Query 轮询或 SSE
- Agent 对话：可选 SSE 流式；每轮落盘 `sessions/{sessionId}.json`

---

### 5.2 感知层 — `hcp-twin-mcp`（MCP Server）

遵循 **mcp-server-patterns**：业务逻辑与传输解耦；Zod 校验每个 Tool；错误返回结构化消息供模型理解。

#### 5.2.1 Tools（P0）

| Tool | 输入 | 输出 | 幂等 |
|------|------|------|------|
| `resolve_hcp_identity` | name, hospital, dept | `hcpId`, url_candidates[] | 是 |
| `build_twin` | hcpId, mode=full\|incremental | `runId` | 否（增量可重复） |
| `get_twin_status` | runId | phase, progress, error? | 是 |
| `get_twin` | hcpId | twin.json | 是 |
| `get_insights` | hcpId | insights.json | 是 |

#### 5.2.2 Resources（P1，可选）

| URI 模式 | 内容 |
|----------|------|
| `twin://{hcpId}/career` | 职业轨迹 JSON |
| `twin://{hcpId}/research` | 论文与主题聚类 |
| `twin://{hcpId}/heatmap` | 90/60/30 天活动切片 |

Resources 供 Cursor / 外部 MCP Client 只读拉取；产品 UI 仍走 BFF。

#### 5.2.3 Collector 流水线

```text
Stage A  身份锚点     姓名+医院+科室 → 主页 URL + Scholar/ORCID
Stage B  职业轨迹 P0  医院/大学页 → career-timeline.json
Stage C  科研动向 P0  PubMed + 消歧 + 主题聚类 → research.json
Stage D  活动热力 P1  会务/新闻 cron → heatmap/snapshots.json
Stage E  Insights     themes = 论文主题 ∩ 演讲主题 ∩ 政策发声（分桶）
```

| Collector | 数据源 | 自动化 |
|-----------|--------|--------|
| Career | 医院/大学官网 | Playwright + 结构化抽取 |
| Research | PubMed E-utilities | HTTP API；**作者消歧** 必做 |
| Heatmap | 科室新闻、会议平台 | 异步；无公开证据须标 `no_public_evidence` |

#### 5.2.4 传输

| 环境 | 传输 |
|------|------|
| 本地 / Cursor | `stdio` |
| 生产 / Web BFF | **Streamable HTTP** `:3200` |

### 5.3 知识层 — `packages/medical-kb`（RAG）

遵循 **rag-implementation**：Dense + Sparse Hybrid、Rerank、分索引、强制 citation。

#### 5.3.1 为何双索引

| 索引 | 内容 | 检索时机 |
|------|------|----------|
| `academic_index` | 指南、论文摘要、试验 | 话题、证据、unmet need |
| `compliance_index` | RDPAC、IFPMA、办法摘要、客户 SOP | **每次生成前强制** |

学术与合规 **不可混库**：过滤维度、切块策略、失败策略不同。

#### 5.3.2 检索管线

```text
Query（由 Twin themes + 任务类型生成）
    │
    ├─► academic_index
    │     filter: specialty, year, language
    │     hybrid: BGE-M3 dense + BM25 sparse
    │     fuse: RRF (dense 0.7 / sparse 0.3)
    │     rerank: bge-reranker-v2-m3 → top-5
    │
    └─► compliance_index
          filter: jurisdiction=CN, tenant_id
          clause-aware chunk + rerank → top-5

Merge → chunks[] with {text, source, version, clause_id, score}
```

#### 5.3.3 Ingest 策略

| 类型 | 策略 |
|------|------|
| Compliance | P0 种子库（RDPAC PDF 按条款切块）；与病种无关 |
| Academic | **按需**：Twin 产出 `specialty/themes` 后触发 PubMed + 指南拉取 |
| Manifest | 每次 ingest 写 `data/rag/ingest-manifest.json`（版本、as_of、doc_id） |

不做一次性全 PubMed 灌库。

#### 5.3.4 Chunk 与 Parent-Document

| 文档类型 | 切块 |
|----------|------|
| 合规准则 | 按条款号；payload 含 `clause_id` |
| 论文 | 摘要整段；全文按 section |
| 指南 | 按章节；`authority` 标卫健委/学会 |

召回用小块；生成时可拉回 parent 段落（P2）。

### 5.4 决策层 — `hcp-engagement-agent`

遵循 **agent-builder**：P0 五个 Capability；Knowledge 按需经 tool 注入；Context 保护（截断冗长 RAG）。

#### 5.4.1 Agent 循环（概念）

```text
LOOP:
  模型看到：system（短） + 会话 + tool_results
  模型决定：调用 tool 或回复用户
  若 tool：执行 → 结果写入 context → 继续
  若回复：返回 Options / 修订稿 → 落盘 JSON
```

#### 5.4.2 P0 Capabilities

| Tool | 类型 | 说明 |
|------|------|------|
| `get_twin_insights` | 读 | `data/twins/{hcpId}/insights.json` |
| `retrieve_academic` | 检索 | 调 `medical-kb`；带 specialty 过滤 |
| `retrieve_compliance` | 检索 | **硬约束**；无命中则 gate 降级 |
| `propose_engagement_options` | 写 | 3–5 条 Options → `engagements/.../options/` |
| `revise_engagement` | 写 | 读 session，按反馈改 Options |

#### 5.4.3 LangGraph 薄编排（主路径）

```mermaid
stateDiagram-v2
    [*] --> LoadInsights: propose_options
    LoadInsights --> ParallelRetrieve
    ParallelRetrieve --> Academic: retrieve_academic
    ParallelRetrieve --> Compliance: retrieve_compliance
    Academic --> Gate
    Compliance --> Gate
    Gate --> Generate: 合规命中
    Gate --> Degrade: 无合规命中
    Generate --> ComplianceCheck
    ComplianceCheck --> Persist
    Degrade --> Persist
    Persist --> [*]
```

| 节点 | 行为 |
|------|------|
| `compliance_gate` | 敏感互动（院内会、讲者费等）无合规 chunk → 拒答或标注「需人工合规确认」 |
| `compliance_check` | 调用 `cn-hcp-compliance` 规则或 LLM 闸门（Fail-fast） |
| `generate` | 每条 Option 含 `academic_refs[]`、`compliance_refs[]`、旁注 |

**对话路径**（Assistant）：同一 Agent，`revise_engagement` 由模型自主决定是否再检索；不强制重跑全图。

#### 5.4.4 Knowledge 加载策略

| 知识 | 加载方式 | 禁止 |
|------|----------|------|
| cn-hcp-pro 模板 | 短 system 或 skill 片段 | 全文塞入 prompt |
| RAG chunks | 仅 tool_result | 预加载整库 |
| Twin | `get_twin_insights` | 塞入完整 twin.json |
| 客户 SOP | compliance 检索 tenant 过滤 | 明文进 system |

#### 5.4.5 Permissions（硬边界）

- 不编造 NMPA 说明书外疗效
- 院内活动旁注：机构同意 + 代表备案
- 仅公开信息进 Twin
- 输出 **不替代** MLR

## 6. 核心数据流

### 6.1 端到端：建 Twin → 出 Options

```mermaid
sequenceDiagram
    actor U as 用户
    participant W as apps/web BFF
    participant M as hcp-twin-mcp
    participant J as data/ JSON
    participant A as hcp-engagement-agent
    participant K as medical-kb
    participant Q as Qdrant
    participant L as Qwen

    U->>W: 录入 HCP 身份
    W->>M: build_twin(hcpId)
    M->>M: Collectors 抓取+消歧
    M->>J: 写 twin.json, insights.json
    W-->>U: Insights 页展示

    U->>W: 生成 Engagement Options
    W->>A: propose_engagement_options(hcpId)
    A->>J: get_twin_insights
    A->>K: retrieve_academic + retrieve_compliance
    K->>Q: hybrid search
    Q-->>K: chunks
    K-->>A: 引用块
    A->>L: 生成 Options
    A->>J: 写 options/{runId}.json
    W-->>U: Options 列表+引用

    U->>W: Assistant 修订
    W->>A: revise_engagement(sessionId, feedback)
    A->>J: 读/写 session.json
    W-->>U: 修订后 Options
```

### 6.2 On-demand 学术 Ingest（Twin 触发）

```text
insights.json 产出 specialty/themes
    → BFF 或 Agent 调用 medical-kb.ingest_on_demand()
    → PubMed / 指南拉取 → 切块 → embed → upsert academic_index
    → 更新 ingest-manifest.json
    → 后续 retrieve_academic 可命中新专科内容
```

## 8. 安全与合规架构

```text
┌────────────────────────────────────────┐
│  人审 MLR（客户流程，系统外）            │
├────────────────────────────────────────┤
│  cn-hcp-compliance Fail-fast（生成后）   │
├────────────────────────────────────────┤
│  compliance_gate（生成前，无 chunk 降级）│
├────────────────────────────────────────┤
│  retrieve_compliance（强制检索）         │
├────────────────────────────────────────┤
│  仅公开数据源 + 说明书边界提示           │
└────────────────────────────────────────┘
```

| 控制点 | 实现 |
|--------|------|
| API Key | 仅 server 进程；不进浏览器 |
| 数据驻留 | Qdrant + JSON 本地/客户 VPC；无默认公有云向量 SaaS |
| 审计 | Options 保留 refs + `as_of` + `runId`；session 全量留痕 |
| 采集合规 | 不爬登录态处方系统；不冒充 CRM 活动记录 |
| 输出声明 | 固定 `mlr_status: draft_not_reviewed` |

## 9. 可观测性与运维

| 维度 | P0 | P1+ |
|------|-----|-----|
| 健康检查 | `GET /api/health`：JSON 可写、Qdrant、MCP ping | — |
| 任务追踪 | `runId` + status JSON | Redis + Bull Board |
| RAG 质量 | ingest-manifest 版本 | eval-set.json 回归；命中率周看 |
| Agent | Options 是否含双引用 | Fail-fast 触发率；修订率 |
| Twin | collector phase 日志 | 热力 cron 空窗告警 |
| 成本 | LLM token 日志；PubMed 限速 | 按 hcpId 聚合 |

**模型与索引版本**（ai-architect 实践）：

- Embedding / Rerank / LLM 模型名写入 manifest 与 Option metadata
- Qdrant collection 按 `v{major}` 命名；ingest 可重建，不原地破坏性迁移

## 11. 架构决策记录（ADR 摘要）

| ID | 决策 | 理由 | 放弃方案 |
|----|------|------|----------|
| ADR-01 | 主数据 JSON 文件 | 规格要求；MVP 零 DB 运维 | Postgres |
| ADR-02 | Twin 采集独立 MCP 进程 | Playwright 隔离、协议可复用 | Web 内嵌爬虫 |
| ADR-03 | Qdrant 双索引 | 学术/合规过滤与失败策略分离 | 单索引 + prompt 合规 |
| ADR-04 | Hybrid + Rerank | 中英医学词、条款号、MeSH | 仅 dense |
| ADR-05 | Agent 5 tools + 薄 LangGraph | agent-builder；避免僵化工作流 | 20+ tools / 硬编码百步 |
| ADR-06 | 专科按需 ingest | 成本与噪声可控 | 全科预灌 |
| ADR-07 | BFF 网关 | 安全、鉴权、任务抽象 | 浏览器直连 MCP |
